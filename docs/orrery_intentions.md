# Orrery Intentions: The Project Chassis Map

## Status

This map describes the Orrery project chassis at commit `9ac0caf6` on `main`, as issue #782 ("Turn Durable Intentions Into Executable Opportunities") will evolve it. The owner's ruling on #782 (Arachne sequence 39, 2026-09-30) reads: "Disposition: Build" and "Foreground intentions per character: A small configured number". The ruling makes the cap a tunable in `nexus.toml`, read through the Pydantic settings models. This map decides nothing the ruling does not decide.

## Schema

The chassis is the table `character_project_states`. Eight migrations define it: `074_plan_relocation_projects.sql`, `077_recruit_ally_projects.sql`, `081_faction_project_contexts.sql`, `084_build_venture_projects.sql`, `085_pursue_romance_projects.sql`, `086_court_patron_projects.sql`, `087_seek_redemption_projects.sql` and `096_polymorphic_patron.sql` (`git grep -ln character_project_states migrations/`). Read the live definition with `psql -d NEXUS_template -c '\d+ character_project_states'` and the `COMMENT ON` statements in those migrations. The comments are the column documentation; this map does not restate them.

## Draft Closed Trigger Union

This union is a draft. The four members are the ones #782 closes on.

Clock rule, for every member: truth is read on the world clock (`chunk_metadata.world_time`; see migration 118's comment) or on event occurrence time, never on ticks. Ticks serve only ordering, replay, exposure fairness, habituation and narration cadence. ## Measuring Gaia Revision Weight

`scripts/qa_shift/intention_revision_weight.py` measures the grammar and context cost of two Gaia revision channels against the static Gaia wire. It opens no database connection, makes no network request and calls no provider. Run it from the repository root:

```bash
PYTHONPATH=$PWD python scripts/qa_shift/intention_revision_weight.py
PYTHONPATH=$PWD python scripts/qa_shift/intention_revision_weight.py --open-counts 0,1,2,3,5,10,20
```

It prints one JSON document. Its keys mean:

- `model_id`: the Gaia seat's configured default model (`apex.gaia_model`, else `apex.model`), whose registered local tokenizer counts every number.
- `baseline`: the sentence that states what the baseline wire is. It reads: "static SkaldGaiaWire; the OpenAI seat sends the database-specialized SkaldGaiaRegistryWire (gaia_registry_schema.py:497), so absolute strict counts differ from production; the deltas are the measurement"
- `verb_set` and `probe_shape`: the probe wires are an upper bound for measurement (four verbs, three target fields, urgency 1 to 3), not a ruling on the open verb or urgency questions.
- `grammar`: tokens per wire (`baseline`, `option_1_new_field`, `option_2_replace_path`) and per grammar kind. `strict` is the schema the OpenAI wire sends; `lenient` is the omittable-field schema the local wire sends; `prompt_guide` is the guide text the Anthropic prompted transport appends.
- `grammar_delta`: each option's grammar tokens minus the baseline's, per kind. Option 1 adds a new closed `intention_revisions` field to the Gaia wire, addressed by intention id. Option 2 adds an `intention_revision` delta to the adjudication replace path, addressed by the card's `proposal_id`.
- `rendered_context`: the tokens of the intention listing Gaia reads each turn, per open-intention count. Option 1 needs a listing of every open intention; option 2 needs none, because the card already names the intention.
- `per_call_growth`: the grammar delta plus the listing tokens, per option, grammar kind and open count. This is the growth of one Gaia call.
